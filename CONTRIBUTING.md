# Cómo contribuir al desarrollo

## Flujo corto

1. Abre o selecciona un issue.
2. Define resultado esperado y criterios de aceptación.
3. Crea una rama (`feature/`, `fix/`, `data/` o `docs/`).
4. Realiza cambios pequeños y verificables.
5. Ejecuta las validaciones del README.
6. Abre una solicitud de cambio y pide revisión.

No se trabaja directamente sobre `main`.

## Revisión

- La revisión técnica comprueba código, enlaces, comportamiento y accesibilidad.
- La revisión de producto y datos comprueba términos, fuentes, reconocimiento, navegación y alcance público.
- Los cambios de estructura de datos o política de publicación requieren aprobación explícita del responsable de datos.

## Datos públicos

No añadas al repositorio archivos recibidos de terceros, datos de trabajo, enlaces internos ni campos de proceso. Los JSON públicos deben ser generados por el pipeline privado y revisados antes de integrarse.
